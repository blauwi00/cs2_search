# CS2 Market Bot

Telegram-бот, который круглосуточно следит за ценами предметов CS2, ищет разницу цен между
Skinport/CSFloat и Steam Market, учитывает комиссии и присылает уведомления. Все суммы — **в гривне (UAH)**.
Бот **ничего не покупает и не продаёт** сам и никогда не просит доступ к Steam-аккаунту.

Работает бесплатно: Cloudflare Workers (Free) + D1 + Cron Triggers + Telegram Bot API.

| Этап | Статус |

| 1. Ядро: Worker, webhook, D1, Cron, планировщик, реальные цены, нормализация, история, уведомления, состояние системы | ✅ |
| 2. Арбитраж: Skinport/CSFloat → Steam, комиссии Steam, курсы НБУ, ликвидность, приоритеты, защита от повторов | ✅ |
| 3. Интерфейс: графики цен (страница с SVG), раздел кейсов с динамикой 7/30 дн, фильтры сделок (площадка, категория, бюджет, ликвидность) | ✅ |
| 4. Инвентарь и журнал сделок: «Купил»/«Продал», раздельный учёт Steam Wallet / External Cash / оценка инвентаря, статистика, уведомления по инвентарю и цели продажи | ✅ |
| 5. Аналитика: проверка каждого сигнала через 24 ч, качество по категориям, сравнение расчёта с твоими реальными сделками, проверка правил на истории без заглядывания в будущее, более частый опрос волатильных предметов и свежих сделок | ✅ |

Проверено автоматически: **65 тестов проходят**, проверка типов `tsc` без ошибок, сборка Worker — 189 КБ.
**Не проверено**: реальный деплой в Cloudflare и реальные ответы площадок из Worker — из среды разработки
сайты площадок недоступны. Это проверяется после развёртывания адресом `/admin/diag` (раздел 6, шаг 12).
Пока этот шаг не пройден, бот нельзя считать принятым по критериям ТЗ.

Чего бот сознательно **не** делает: не покупает и не продаёт сам; не определяет статус кейса «в дропе / снят»
(надёжного бесплатного источника нет); не оценивает редкие паттерны (Blue Gem, фазы Doppler) — такие сделки только с низким приоритетом;
не читает инвентарь Steam (учёт ручной — без доступа к аккаунту).

## 2. Технические решения (кратко)

**Валюта.** Пользователь видит только UAH. Steam отдаёт цены сразу в гривне (`currency=18`).
Skinport гривну не поддерживает → берём EUR и пересчитываем по курсу НБУ. CSFloat — центы USD → по курсу НБУ.
В базе хранятся и исходная цена, и курс: поэтому колебание курса гривны **не** выдаётся за рост/падение предмета
(изменения цен считаются в исходной валюте площадки).

**Деньги** — только целые числа (копейки/центы), без float.

**Комиссия Steam** считается не коэффициентом 0,85, а алгоритмом Steam: 5% (Steam) + 10% (CS2), каждая с округлением вниз
и минимумом; цена покупателя 100,00 → продавцу 86,97. Для UAH минимальная комиссия (1 коп.) — **допущение**:
отдельной документации не нашлось, влияет только на предметы дешевле ~1 грн.

**Ориентир продажи в Steam** — консервативный: меньшее из «самое дешёвое объявление − 1 коп.» и «медиана продаж за 24 ч».

**Ликвидность** — только по завершённым продажам (Steam за 24 ч, Skinport за 7 дней). Число объявлений продажами не считается.

**Три категории сигналов:** проверяемый спред / оценочная возможность / ценовая аномалия.
Высокий приоритет запрещён, если: данные устарели, курс устарел, неизвестно наличие, нет данных о продажах,
ликвидность ниже порога, предмет зависит от паттерна/фазы/float (ножи, перчатки, Case Hardened, Doppler, Fade…),
у Steam есть только один показатель из двух, сделка дороже бюджета.

**Лимиты бесплатного Cloudflare** (проверены в документации 04.11.2026):
100 000 вызовов Worker в день, **10 мс CPU** на вызов, **50 внешних запросов** и **50 запросов к D1** за вызов
(`db.batch()` = 1 запрос), база D1 до 500 МБ. Бот сам считает запросы и останавливает работу заранее,
продолжая в следующую минуту. В тесте со 100 предметами — до 45 запросов к D1 за вызов.

**Реальная скорость охвата** (честно): Steam — около 5–6 предметов в минуту (неофициальный адрес, держим нагрузку низкой),
то есть 100 предметов обновляются примерно за 20 минут. Skinport — весь список одним запросом раз в 10 минут.
Сканировать «весь рынок за минуту» бесплатная инфраструктура не позволяет.

**Риск лимита CPU.** Каталог Skinport `/v1/items` — несколько мегабайт. Бот не делает `JSON.parse` целиком, а потоково
ищет только нужные предметы. Если всё равно упрётся в 10 мс CPU, платформа оборвёт запуск; бот это замечает и после 3 подряд
оборванных запусков **сам отключает задачу** и пишет об этом в «Состояние системы» (там же кнопка «Включить»).

## 3. Источники данных

| Источник | Документация | Endpoint | Ключ | Лимит | Что даёт | Ограничения |
|---|---|---|---|---|---|---|
| Steam Market | официальной нет | `steamcommunity.com/market/priceoverview/?appid=730&currency=18&market_hash_name=…` | нет | не опубликован, при частых запросах — 429 | самое дешёвое объявление, медиана и число продаж за 24 ч, в UAH | **неофициальный** адрес (используется сайтом Steam) → «ограниченный режим»: мало запросов, backoff по Retry-After. Ордера покупки и полная история без авторизации недоступны — не используются |
| Steam поиск | официальной нет | `steamcommunity.com/market/search/render/?…&norender=1` | нет | как выше | точные `market_hash_name` для поиска в боте | только для поиска названий |
| Skinport | [docs.skinport.com](https://docs.skinport.com/) | `/v1/items`, `/v1/sales/history` | нет | 8 запросов / 5 мин, кэш 5 мин, обязателен `Accept-Encoding: br` | мин. цена и число объявлений; медианы и объёмы продаж 24ч/7д/30д/90д | UAH нет → EUR; конкретных объявлений (float/паттерн) API не даёт; комиссии платёжных методов не указаны |
| CSFloat | [docs.csfloat.com](https://docs.csfloat.com/) | `/api/v1/listings?market_hash_name=…&sort_by=lowest_price` | **нужен** (профиль → Developer) | указываются для каждого endpoint, есть лимит по IP | конкретные объявления с float и паттерном, центы USD | без ключа выключен; бесплатность ключа и лимиты проверь у себя в профиле |
| НБУ | [bank.gov.ua](https://bank.gov.ua/) | `/NBUStatService/v1/statdirectory/exchange?json` | нет | — | официальные курсы USD/EUR/PLN к гривне | официальный курс ≠ курс твоего банка/платёжки |

Обход защит, прокси и смена IP не используются. Если источник запрещает доступ — он помечается недоступным.

## 4. Настройки по умолчанию (меняются в боте: ⚙️ Настройки)

| Параметр | По умолчанию | Почему |
|---|---|---|
| Мин. разница после комиссий | 20 грн | меньшая разница легко «съедается» колебанием цены во время ожидания |
| Мин. доходность | 8% | при падении цены на 5–10% до продажи должен оставаться запас |
| Мин. ликвидность для высокого приоритета | средняя (≥10 продаж в день) | без покупателей разница ничего не стоит |
| Порог изменения цены | 15% | меньшие колебания для скинов — шум |
| Уведомлений в час | не больше 6 | защита от спама |
| Тихие часы | 23:00–8:00 по Варшаве | |
| Данные устаревают через | 30 мин | Skinport обновляется раз в 5 мин, Steam — порциями |
| Уведомлять с приоритета | средний | низкий приоритет (аномалии, ножи с паттернами) сохраняется, но не присылается |
| Сводка | 20:00 по Варшаве | |

Повтор уведомления по той же сделке — только если разница или цена изменились больше чем на 20% и прошло ≥ 6 часов.
Если сделка исчезла, бот **правит** старое сообщение («⚫ НЕАКТУАЛЬНО»), а не шлёт новое.

## 5. Структура проекта

```
src/
  index.ts              — вход Worker: /telegram, /admin/*, Cron
  env.ts                — секреты и привязки

  demo.ts               — DEMO: расчёт на тестовых данных с явной пометкой
  api/                  — адаптеры: steam.ts, skinport.ts, csfloat.ts (единый формат Quote)
  currency/nbu.ts       — курсы НБУ, пересчёт в копейки
  chart.ts              — страница графика цен (SVG), ссылка подписана HMAC
  core/
    portfolio.ts        — себестоимость, оценка инвентаря, реализованный результат по кошелькам
    quality.ts          — итог сигнала через 24 ч, backtesting без будущих данных
    normalization.ts    — разбор market_hash_name: износ, StatTrak, Souvenir, категория, «цена зависит от экземпляра»
    matching.ts         — можно ли сравнивать два предмета
    fees.ts             — комиссия Steam (алгоритм Steam) и реестр комиссий
    arbitrage.ts        — purchase_cost, expected_seller_proceeds, net_spread, return_on_cost, break_even_price, downside
    liquidity.ts        — ликвидность по продажам

    analyzer.ts         — резкие изменения цены, статистика
    alerts.ts           — дедупликация, cooldown, тихие часы, лимит в час
    scheduler.ts        — задачи, блокировки, backoff, защита от двойного Cron
    pipeline.ts         — Fetch → Validate → Normalize → Store → Analyze → Score → Confirm → Notify
    runner.ts           — один запуск Cron в пределах лимитов
  storage/db.ts         — запросы к D1; trades.ts — инвентарь и продажи; budget.ts — учёт лимитов вызова
  telegram/             — api.ts, webhook.ts, menus.ts, inventory.ts, messages.ts, settings.ts, context.ts
migrations/0001_init.sql, 0002_inventory_trades_quality.sql
tests/                  — 65 тестов (node:test + встроенный SQLite, тот же SQL, что у D1)
fixtures/               — вымышленные ответы API для тестов
```

## 6. Развёртывание с iPhone

Нужно: аккаунты Telegram, GitHub, Cloudflare. Компьютер не нужен.

### Шаг 1. Бот в BotFather
1. В Telegram открой **@BotFather** → `/newbot`.
2. Введи имя (например `CS2 Market`) и username, заканчивающийся на `bot`.

### Шаг 2. Токен
BotFather пришлёт строку вида `123456789:AA…`. Это **TELEGRAM_BOT_TOKEN**. Никому её не отправляй и не клади в GitHub.

### Шаг 3. Твой Telegram ID
Напиши **@userinfobot** любое сообщение — он ответит числом `Id`. Это **ADMIN_TELEGRAM_ID**.

### Шаг 4. Код в GitHub
Создай **приватный** репозиторий `cs2-market-bot` и загрузи туда файлы проекта
(или дай мне имя пустого репозитория — я загружу код сам).

### Шаг 5. База D1
1. Cloudflare → **Storage & Databases** → **D1 SQL Database** → **Create Database**.
2. Имя: `cs2-market-bot` → **Create**.
3. Скопируй **Database ID**.
4. В GitHub открой `wrangler.jsonc` → значок карандаша → замени `REPLACE_WITH_YOUR_D1_DATABASE_ID` на этот ID → **Commit changes**.

### Шаг 6. Привязка базы к Worker
Делается автоматически: в `wrangler.jsonc` уже указан binding `DB`. Отдельно в панели ничего привязывать не нужно.

### Шаг 7. Worker из GitHub
1. Cloudflare → **Workers & Pages** → **Create application** → **GitHub** → разреши доступ к репозиторию.
2. Выбери `cs2-market-bot`.
3. В настройках сборки укажи **Deploy command**: `npm run deploy`
   (команда сама применит миграции базы и задеплоит Worker).
4. **Save and Deploy**. Дождись зелёного статуса сборки.
   Если сборка упала на миграциях — запасной путь в шаге 10.

### Шаг 8. Секреты
Workers & Pages → `cs2-market-bot` → **Settings** → **Variables and Secrets** → **Add** → тип **Secret**:

| Имя | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен из шага 2 |
| `ADMIN_TELEGRAM_ID` | число из шага 3 |
| `TELEGRAM_WEBHOOK_SECRET` | придумай 32+ символа: латиница, цифры, `_`, `-` |
| `ADMIN_KEY` | другая случайная строка 32+ символа |
| `CSFLOAT_API_KEY` | необязательно: ключ из профиля CSFloat → Developer |

Нажми **Deploy**.

### Шаг 9. Cron
Ничего делать не нужно: расписание `* * * * *` задаётся в `wrangler.jsonc`.
Проверка: **Settings** → **Triggers** → **Cron Triggers** — там должна быть одна строка «каждую минуту».
Менять расписание в панели не стоит: следующий деплой его перезапишет.

### Шаг 10. Миграции базы
Обычно уже выполнены в шаге 7. Если нет (сборка упала или в шаге 12 «D1: ошибка»):
Cloudflare → D1 → `cs2-market-bot` → **Console** → вставь целиком содержимое `migrations/0001_init.sql` → **Execute**,
затем так же `migrations/0002_inventory_trades_quality.sql`.
Файл 0001 можно запускать повторно без вреда. Файл 0002 — **только один раз** (он добавляет столбцы; повтор выдаст ошибку «duplicate column», это значит, что он уже применён).

### Шаг 11. Webhook Telegram и проверка /start
1. Адрес Worker: страница Worker → домен вида `https://cs2-market-bot.<твой-поддомен>.workers.dev`.
2. Открой в Safari: `https://<адрес>/admin/setup?key=<ADMIN_KEY>`.
3. Должно быть: «D1: OK», «Webhook: установлен», «Тестовое сообщение: отправлено».
4. В Telegram нажми `/start` — появится меню.

### Шаг 12. Тестовый сбор и диагностика
1. Безопасная проверка оформления: `/demo` — пришлёт уведомление с пометкой «🧪 DEMO — тестовые данные».
2. Диагностика реальных источников: `https://<адрес>/admin/diag?key=<ADMIN_KEY>` — проверяет D1, Telegram, НБУ, Steam, Skinport, CSFloat **настоящими запросами** и присылает отчёт в Telegram.
3. Добавь предмет: **👁 Мониторинг цен** → **➕ Добавить предмет** → напиши, например, `redline`.
4. Принудительный сбор сразу: `https://<адрес>/admin/run?key=<ADMIN_KEY>`.

### Как пользоваться каждый день
- **💰 Выгодные сделки** — активные возможности; кнопки фильтров внизу. В карточке: «✅ Купил», «История цены».
- **👁 Мониторинг цен** — список наблюдения; в карточке предмета: цены, ликвидность, «📈 График», «🎯 Целевая цена», «🧪 Проверить на истории».
- **📦 Кейсы** — кейсы и капсулы из наблюдения с изменением за 7 и 30 дней.
- **🎒 Мой инвентарь** — «➕ Добавить предмет» (что у тебя уже есть или купил), карточка позиции: «💸 Продал», «🎯 Цель продажи».
- **🧾 История сделок** — реальный результат отдельно по Steam Wallet и External Cash.
- **📈 Аналитика** — статистика сканера и качество сигналов (проверка через 24 ч).

### Шаг 13. Реальные уведомления
Включены по умолчанию (**⚙️ Настройки** → «Уведомления: вкл»). Они приходят, когда у предмета есть свежие цены и Steam,
и Skinport/CSFloat, а разница после комиссий выше порогов. Совет: начни с 10–30 ликвидных недорогих предметов и кейсов.

### Шаг 14. Обновление кода
Любой коммит в основную ветку GitHub (в том числе правка файла в браузере на iPhone) → Cloudflare сам пересоберёт и задеплоит.
Статус: Worker → **Deployments** / **Builds**.

### Шаг 15. Где смотреть ошибки
- В боте: **🩺 Состояние системы** — источники, последние ошибки, задачи, курсы, счётчики запросов.
- Cloudflare: Worker → **Logs** (Workers Logs включены в `wrangler.jsonc`) и **Settings** → **Trigger Events** → **View events** (последние 100 запусков Cron).
- Если источник недоступен дольше 30 минут — придёт одно техническое предупреждение.

## 7. Безопасность

- Управлять ботом может только `ADMIN_TELEGRAM_ID` и только в личном чате; чужие сообщения игнорируются.
- Webhook проверяет заголовок `X-Telegram-Bot-Api-Secret-Token` (сравнение за постоянное время), размер тела ≤ 64 КБ.
- `/admin/*` закрыты ключом `ADMIN_KEY`. Ключ передаётся в адресе — не пересылай эти ссылки; при утечке смени секрет.
- Секреты только в Cloudflare Secrets, в ответы и логи не попадают.
- SQL — только подготовленные запросы с параметрами.
- Кнопки-ссылки — только `https://` на `steamcommunity.com`, `skinport.com`, `csfloat.com` и на страницу графика самого бота.
- Страница графика открывается только по ссылке с подписью HMAC (ключ `ADMIN_KEY`); без подписи — 403.
- Никаких паролей Steam, Steam Guard, cookies, автоматических покупок.

## 8. Тесты (для разработки)

```
npm test          # 65 тестов, нужен Node.js ≥ 22.18
npm run typecheck # проверка типов
```

Тесты используют встроенный SQLite Node — тот же диалект SQL, что у D1, — поэтому проверяют и сами миграции.
Покрыто: сопоставление, StatTrak/износ/паттерны, курсы, комиссии и округление, положительный/отрицательный спред,
ложный арбитраж из-за валют, дедупликация, cooldown, 429/500, устаревшие и отсутствующие данные, ошибки JSON,
защита webhook, доступ только администратору, настройки, ссылки, миграции, повторный Cron, блокировки,
исчерпание лимита, нулевой бюджет, «выгодно до комиссий — убыточно после», нож с неизвестным паттерном,
колебание курса без изменения цены, устаревший курс, журнал сделок (покупка/продажа/запрет перепродажи), раздельный учёт кошельков,
уведомления по инвентарю, подпись ссылок графиков, пропуски данных на графике, фильтры сделок, backtesting без будущих данных,
проверка качества сигналов, соблюдение лимитов вызова с инвентарём.

Развернуть по разделу 6 и открыть `/admin/diag`. Всё, что покажет диагностика на реальных данных
(формат ответа площадки, лимиты Steam, лимит CPU для каталога Skinport), исправляется уже по факту.
